# MCFPP：面向 Minecraft 数据包的高级编程语言

做 Minecraft 数据包的时候，写下前几条命令往往很有成就感；但当玩法逻辑逐渐复杂起来，原版 `mcfunction` 在代码组织上的局限就会越来越明显。

比如算一个稍微复杂的数值公式，往往得拆成好几行 `scoreboard players operation`；写一段带条件分支或循环的技能，就得把完整的逻辑拆进好几个 `.mcfunction` 文件里来回跳转；想给函数传个参数，还得自己约定临时记分板或者 storage 路径。工程规模一大，大量精力都会花在记分板调度和文件管理上。

MCFPP 就是为了改善这种开发体验而设计的。它把现代编程语言中的变量、表达式、控制流、带参函数和数据结构引入了数据包开发，同时支持在代码中直接内联原版命令，最后由编译器统一构建为标准的 Minecraft 数据包。

现在，**MCFPP 0.1.0** 首个公开测试版正式发布，编译器、标准库、CLI 命令行工具和工程模板均已就绪，欢迎各位数据包开发者上手试用！

在 0.1.0 版本中，你可以体验到：

- **结构化逻辑编写**：支持整数、浮点数、布尔运算、`if / else` 分支、`while` 循环，以及带参数与返回值的函数。
- **数据与功能复用**：通过 `data` 将零散的属性与方法封装在一起，支持将通用模块打包为库跨项目调用。
- **原版命令与数据互通**：支持直接内联原版 Minecraft 命令、内插变量，并提供记分板与 NBT 读写接口。
- **配套工程工具链**：通过 CLI 管理工程配置、依赖与目标版本编译，配合 IntelliJ IDEA 插件获得代码补全、实时诊断与重构支持。

> [GitHub 项目仓库](https://github.com/MinecraftFunctionPlusPlus/MCFPP) · [官方文档与教程](https://www.mcfpp.top)

## 围绕逻辑组织代码

先看一个常见的积分结算例子：根据玩家的击杀数计算积分（每次击杀计 5 分，外加 10 分基础分），满 100 分时发放一颗钻石并弹出提示。在 MCFPP 中，这段逻辑可以直接写成一个函数：

```mcfpp
func reward(kills: int) {
    var points = kills * 5 + 10

    if (points >= 100) {
        /give @s minecraft:diamond 1
        /tellraw @s {"text":"获得一颗钻石！","color":"gold"}
    }
}
```

参数 `kills` 直接从函数签名传入，一行算完积分，紧接着用 `if` 判断条件并执行原版命令。底层的临时记分板分配和子函数拆分，全部交由编译器在幕后处理。

这也是 MCFPP 的核心设计思路：**让开发者专注于玩法和逻辑实现，而不必为 `mcfunction` 的文件拆分与记分板调度分心。** 原本需要拆成多个碎片小文件的流程，现在用几行直观的代码就能写在一起。

## 语法简介

> [!NOTE]
> 如果你有其他高级语言，例如 Kotlin、Rust、Java、Typescript 等，的开发经验，你多半能对 MCFPP 的大部分语法感到熟悉owo

MCFPP 的语法结构清晰直观：用大括号 `{}` 划分代码块，每行写一条语句（同行多条语句可用 `;` 分隔），用 `//` 编写注释。下面通过几个例子快速浏览最常用的语法特性。

### 变量与运算

在 MCFPP 中，`var` 用于声明可修改的变量，`const` 用于声明固定不变的常量：

```mcfpp
func prepareReward() {
    const base = 10       // 基础奖励
    var bonus: int = 20   // 额外奖励

    bonus += 5
    var total = base + bonus
}
```

你可以像 `bonus: int` 这样显式标注类型，也可以像 `total` 一样直接赋值，由编译器自动推导类型。日常开发中最常用的内置类型如下：

| 类型 | 表示的数据 | 示例 |
| --- | --- | --- |
| `int` | 整数，适合积分、等级和次数 | `20` |
| `float` | 小数，适合倍率和带小数的数值 | `1.5` |
| `bool` | 条件是否成立 | `true`、`false` |
| `string` | 文本，适合名称和提示内容 | `"森林试炼"` |
| `nbt` | Minecraft 中的 NBT 数据 | `{a: 1, b: "qwq"}` |

数值运算直接写 `+`、`-`、`*`、`/`、`%` 即可，同时也支持 `+=`、`-=`、`*=`、`/=`、`%=` 等复合赋值运算符，编写伤害公式或数值结算时比拼接多条记分板指令省心不少。

### 条件判断与循环

遇到需要根据不同情况执行不同效果的场景，可以直接使用 `if`、`else if` 和 `else`。比如小游戏结束后的段位评价：

```mcfpp
func announceResult(points: int) {
    if (points >= 100) {
        /say 达成金牌评价
    } else if (points >= 50) {
        /say 达成银牌评价
    } else {
        /say 挑战完成
    }
}
```

条件表达式支持 `==`、`!=`、`>`、`<`、`>=`、`<=` 比较，也可以通过 `&&`（且）、`||`（或）、`!`（非）组合出更复杂的触发条件。

需要重复执行某段逻辑时，可以使用 `while` 循环（内部同样支持 `break` 和 `continue`）。例如在当前位置连续生成 3 只僵尸：

```mcfpp
func summonTargets() {
    var count = 0
    while (count < 3) {
        /summon minecraft:zombie ~ ~ ~
        count += 1
    }
}
```

编译器会自动生成底层的循环跳转与条件判断，省去了手写递归函数的麻烦。

### 函数、参数与返回值

在原版数据包里，函数本质上是一串命令列表，很难直接传参或返回结果。而在 MCFPP 中，用 `func` 定义的函数支持完整的参数列表与返回值，类型统一用 `:` 标注：

```mcfpp
func calculateReward(kills: int): int {
    return kills * 5 + 10
}

func previewReward() {
    var points = calculateReward(8) // 计算结果为 50
}
```

像这样把常用的计算公式或演出效果封装成函数后，各个关卡和模块都能直接调用；后续调整数值平衡时，也只需要修改函数本身。

### 数据结构与方法

在制作 RPG 技能、自定义装备或关卡状态时，一个对象往往包含多项关联属性。MCFPP 提供了 `data` 复合数据结构，可以把属性字段、工厂（`new`）和成员函数收拢到一起：

```mcfpp
data Skill {
    var level: int = 1
    var damage: int = 10
    var cooldown: int = 20

    new(level: int) {
        return { level, damage: 10, cooldown: 20 }
    }

    func getDamage(): int {
        return this.damage * this.level
    }
}

func useSkill() {
    var fireball = Skill(3)
    var damage = fireball.getDamage()
}
```

定义好 `Skill` 后，通过 `Skill(3)` 就能创建一个 3 级的技能实例，再调用 `fireball.getDamage()` 即可算出对应等级的伤害。相比于把属性拆散在十几个记分板或 NBT 路径里，用 `data` 组织代码要清晰得多，大型项目也更容易维护。

## 与原版命令配合

在提供高级语言特性的同时，MCFPP 依然保留了对原版命令的直接支持：**只要是以 `/` 开头的一行，就会被直接作为原版 Minecraft 命令处理**。

选择器、粒子、音效、实体生成等大家熟悉的原版指令，可以直接写在函数体、条件分支或循环中；手里已有的 `.mcfunction` 命令片段，也能很方便地迁移到 MCFPP 函数里继续使用。

此外，原版命令中还可以直接用 `${变量名}` 嵌入 MCFPP 变量的值：

```mcfpp
func announceStage() {
    const stageName = "森林试炼"
    /say 正在进入：${stageName}
}
```

命令里的 `@s`、相对坐标 `~ ~ ~` 等依然遵循原版的执行上下文语义。同时，MCFPP 也提供了记分板与 NBT 的读写接口，方便把代码里的计算结果写回游戏，或者读取游戏世界中的实时状态。

如果需要维护跨 Minecraft 版本的数据包，可以在 `mcfpp.toml` 中指定目标版本号，编译器会自动匹配对应版本的标准库与数据包格式；代码中还可以使用 `#if MC >= 26.1` 这样的条件编译指令，轻松处理不同版本间的命令差异。

## 项目组织与开发工具

当工程规模扩大到多个文件时，可以用命名空间（`namespace`）和 `import` 把不同模块组织起来。平时沉淀下来的通用功能——比如数学库、状态机、UI 提示组件——还可以独立打包为库，在其他工程里通过依赖配置直接引入。

编辑器方面，配套的 **IntelliJ IDEA 插件**提供了语法高亮、代码补全、实时语法与类型检查、跳转定义、安全重命名以及一键格式化等功能。写错变量名或传错参数时，在编辑器里就能第一时间看到提示，省去了反复进游戏 `/reload` 排查的时间。

## 获取与使用

MCFPP 0.1.0 需要 **JDK 25** 运行环境，官方发行包提供 ZIP（Windows）与 TAR.XZ（Linux / macOS）两种格式。解压并按包内说明配置好环境变量后，三行命令即可创建并编译你的第一个工程：

```shell
mcfpp init hello
cd hello
mcfpp build
```

对于 Windows 开发者，也可以使用 [Chocolatey](https://community.chocolatey.org/) 进行安装：

```shell
choco install mcfpp -y
```

> [!NOTE]
> 截至本文完成的时候，Chocolatey 仓库尚未将 MCFPP 包审核完毕，暂时无法使用 choco 进行安装。但是总之，你现在可以试试。

编译完成后，`build/hello` 目录下就是生成好的数据包。将它复制到对应版本存档的 `datapacks` 文件夹，进游戏执行 `/reload` 和 `/function hello:main` 就能看到运行效果。工程源码位于 `src/main/mcfpp`，修改代码后再次执行 `mcfpp build` 即可更新数据包。

详细的环境配置与进阶用法可以随时查阅 [MCFPP 官方文档](https://www.mcfpp.top)。
