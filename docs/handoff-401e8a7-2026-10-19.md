## 3. 当前语言表面与迁移方法

这个范围先完善表达式，再统一声明和注释，最后移除源码 `interface` 并将 `dynamic` 更名为 `external`。以下是累计变化后的最终写法。

| 内容 | 当前形式与行为 |
|---|---|
| 变量 | `var x: int = 1`，也可以推导类型；类型标注在名字后 |
| 常量绑定 | `const x = 1`，不加 var；约束再次绑定，不自动保证编译期值或深不可变 |
| 强制运行期 | `external x: int = 1` / `external x = 1`；原 dynamic 已退役，仍要求运行期表示 |
| 导入变量 | 保留 `import var ...` 独立形式 |
| 参数和返回 | `func f(x: int): int { return x }`；旧 `->` 返回标记已退役 |
| 模板字段 | data、object data、匿名 data 内使用 `var` / `const` 明确声明 |
| 抽象契约 | `abstract data Contract { abstract func read(): int; }` |
| 具体实现 | 继承后使用 `override func ...` 满足抽象义务 |
| 普通注释 | `// ...`；旧 # 系列注释不再接受 |
| 文档注释 | `/// Markdown`，连续行组成文档块，保留 Markdown 与必要缩进 |
| 语句边界 | 换行或分号；右花括号前最后一条可省分号；同行语句和 SNBT 数组分号仍有意义 |
| 条件 | if / else if / while / do-while 可省条件括号，条件必须为 bool |
| 换行表达式 | 运算符放在上一行行尾；行首单个 / 视为原版命令，跨行除法将 / 放上一行 |
| 算术 | 一元负号与 `+= -= *= /= %=`，复合赋值读取左值、计算再写回；没有新增 ++ / -- |
| 泛型 | `<T>` 等价于 `<T: type>`；值参数可写 `<N: int>`；type 限泛型参数，旧 `T!` 已退役 |
| 宏调用 | 普通调用、显式 ref、直接 lambda 或静态可解析函数；不表示任意运行时闭包已实现 |

```mcfpp
abstract data CounterContract {
    abstract func read(): int;
}

data Counter: CounterContract {
    var value: int = 0
    override func read(): int { return this.value }
}

func example() {
    external n: int = 1
    n += 2
    if n > 0 {
        /say ready
    }
}
```

该片段用于说明最终形式，本次未重新编译。正式语法入口是 [SourceSyntaxTest](../src/test/kotlin/top/mcfpp/test/SourceSyntaxTest.kt)、[DeclarationsTest](../src/test/kotlin/top/mcfpp/syntax/DeclarationsTest.kt)、[ConditionsTest](../src/test/kotlin/top/mcfpp/syntax/ConditionsTest.kt)。

### 3.1 interface / dynamic 的移除边界

抽象模板使用前置 ABSTRACT DATA。旧 `interface` 和 `data abstract` 声明不再接受，`interface`、`dynamic` 可以作为普通标识符。lexer 的 INTERFACE token、parser 的 interfaceDeclaration 规则及三个声明 visitor 的处理入口已删除。

内部的 MCFPPInterfaceType、MCFPPGenericInterfaceType、DataTemplate.isInterface、接口作用域及其泛型缓存已删除。类型解析、继承、导出、Kryo/NamespaceInfo 元数据、MNI 声明快照与事务日志统一使用 data 模型。抽象契约由 isAbstract 和显式 abstract func 表达；普通和抽象 data 的 TypeId.kind 均为 template。Java/Kotlin 自身 interface 和 JVM 反射检查仍是宿主实现的一部分。

此次删除 token 和 parser rule 会改变后续编号；旧库格式 80 的编号保持方案已结束。库格式升至 81，标准库必须随新 grammar 再生，使用方的旧 mclib 也需重新编译。回归通过 [MniLibrarySyntaxCompatibilityTest](../src/test/kotlin/top/mcfpp/test/MniLibrarySyntaxCompatibilityTest.kt) 检查当前 lexer/parser 词表一致，以及标准库序列化 AST 的标识符读取和实际 Slot 命令执行；不再断言历史编号。

最新阶段已同步标准库 SingleEntity、测试与示例、LSP、IntelliJ、VS Code、Linter 和网站。旧报告中的“泛型 interface”或旧测试名是历史名称，当前源码相关测试已迁移为 abstract data。

## 4. 编译器架构：先建立共同概念

旧结构用 ConcreteVar 和大量 Concrete 子类区分已知值与动态值，变量类还承担存储、转换、入栈和状态标记。新结构把这些职责分开，原 Var 与领域类型作为接入层。

| 问题 | 新概念 | 不要混同 |
|---|---|---|
| 声明了什么、允许怎样写？ | Symbol、声明、TypeId、TypeRelations | JVM 类继承、显示名和 NBT 格式不代替语言身份 |
| 编译器有没有完整值？ | CompilerValue，不可变 typed 快照 | 未知、未初始化、实际 null 各不相同 |
| 数据在哪里、访问选中了什么？ | Place / Location / TypedView | 声明身份不等于物理位置；动态下标要捕获 |
| 此控制路径证明了什么？ | ValueFacts / FlowState / 初始化与子形状事实 | 常量、布局、键存在性不能相互冒充 |

[TypeId](../src/main/kotlin/top/mcfpp/type/TypeId.kt) 区分 builtin、名义声明、applied、包含完整只读值的 specialization、union、selector 与 opaque 身份。缓存 key 不能只用短名或生成名。[CompilerValue](../src/main/kotlin/top/mcfpp/analysis/CompilerValue.kt) 表达数字位、文本、NBT、序列、record、type 等冻结载荷，避免可变 Var/Tag 进入 key。

### 4.1 编译主线

```text
Project / MCFPPFile
  → 版本预处理、解析、声明头及词法环境登记
  → 字段/签名/泛型/继承/注解的声明完成边界
  → DeclarationBinding：纯查询类型与签名
  → 函数编译
       ├─ PrimitiveCompiler → TypedIR、效果和返回形状分析
       ├─ ExprVisitor / ImVisitor → 既有领域编译路径
       └─ MacroCallPipeline → 结构化宏展开和提交
  → StorageAccess：读写、复制、物化、位置和事实维护
  → backend / command：按目标能力生成命令
  → DatapackCreator / LibBinWriter：数据包、库和资源
```

这是职责图，不表示每个表达式必经单一 IR。PrimitiveCompiler 只处理其支持子集；普通语法仍有 visitor 路径，宏必须在实参提前求值之前拦截。各入口共用值、存储和选择合同。

## 5. 核心语义与不可误读的约束

### 5.1 类型、any、object、type

名义类型由声明身份确定：字段相同、底层都用 ByteTag 不产生语言兼容，bool 不等于 byte。object 是普通值的静态公共上界；经 object 访问受公开签名限制。any 擦除公开载荷类型，只有分析已证明实际类型时才能据此绑定运算/重载；没有自动运行时类型标签和反射兜底。

type 仅用于泛型参数，不能经普通变量、字段、object 或 any 偷渡 TypeValue。声明处 out/in 按现有位置规则校验，可变容器不变，当前 ImmutableList 也不变；没有新增星投影或另一套泛型推导。

### 5.2 const、external 与控制流

const 限重新赋值，不自动冻结对象或把未知值变常量；external 要求运行期表示，不能为编译器专用值创造 NBT 编码。未赋值、部分赋值、已赋值与错误状态分别记录。

分支合并只保留所有可达前驱共有事实，循环求不动点，不把首轮常量套给所有迭代。循环局部声明有每轮生命周期，同名嵌套局部各有独立身份和存储。

### 5.3 as、复制和地址

as 建立同一 Place 的类型视图，不做数值转换、构造或复制。普通传值/复制在需要时建立独立位置。未使用视图不强制物化；实际访问必须有可读的来源布局，不能补出 map.entries、缺失字段或旧浮点四分量。

动态下标、负索引、键谓词和返回值在规定求值点捕获。左侧已选中元素后，右侧修改索引或容器，写入仍须使用原捕获位置。捕获地址与复制内容是两个动作。

布局只说明怎样读，不证明字典键存在、字段初始化、长度或常量。未知 dict<list<int>> 参数可以有读取所需布局，但不能因此新增持久初始化事实。

### 5.4 效果与项目隔离

EffectAnalysis 描述调用读写/替换的位置；未知调用和原始命令保守清除相关事实，父位置整体写入会使旧后代信息失效。纯调用可以保留合法证据。

同进程连续编译要重置模块、元数据/类型缓存、名字和上下文，避免上个项目或旧目标浮点模块泄漏。ProjectIsolationTest 维护此边界。

## 6. 集合、调用和控制流的累计变化

### 6.1 集合能力

| 类型 / 操作 | 已接入内容 | 边界 / 主要测试 |
|---|---|---|
| list | 下标、add/prepend/addAll/prependAll/insert/removeAt/clear、查询和按值删除 | 自追加先捕获源副本；移动保留编码/子形状；ListIR/QueryIR/MemberTest |
| dict | 已知键及 remove/clear/merge 等成员和整体合并 | 未知字符串键、运行时空字段名明确诊断；DictionaryIR/MemberTest |
| map | 字符串值键、下标、六个成员、keys/keyValueSet 投影 | entries 布局；视图按键定位；投影独立；MapIR/ProjectionIR/MemberTest |
| ImmutableList | 共享位置、查询、参数/返回、编译器值 | 限槽写入及变更成员，不深冻结；ImmutableListTest |
| NBT 数组 | byte/int/long 格式、字面量、复制、物化、下标、参数/返回/循环 | 保留三种 ArrayTag；long 不经 int 截断；NbtArrayIR/Test |
| 编译器专用集合 | 有限静态载荷、嵌套复制、静态视图与擦除事实 | external/as 不自动赋予运行期编码；CompilerOnlyView/CollectionStorageTest |

操作逐步接入 TypedIR，非 IR 路径也复用 ListOperations、DictionaryOperations、MapOperations、ListSearch、NbtEncoding，避免重复命令实现。旧目标限制列表元素 NBT 格式，物理兼容不改变语言身份。未知范围写入只保留共同证据；副本、投影、批量变更和返回都要区分复制与共享。

### 6.2 调用和递归

普通 IR 调用使用真实帧载荷；实参在求值点捕获，返回值立即保存独立位置，避免连续/嵌套调用覆盖前值；static 参数沿原位置写回。

跨调用可传递元素类型、子字段形状和长度，但调用边界清除普通常量值，不按常量实参预执行任意函数。返回分支保留共同形状；递归对同形输入迭代求解返回/写回摘要。入口：IRCallTest、CallShapeIRTest、EffectAnalysisTest、ErasedFlowTest、StorageViewTest。

### 6.3 循环、范围与作用域

do-while 与闭合整数区间 for 已有 IR 控制流。端点按顺序捕获，包含上界，递增前判断结束以防 Int.MAX_VALUE 回绕。循环变量是每轮可变副本，改它或原范围不改变迭代进度。

命名、擦除、嵌套范围在证明端点为 int 时使用对应路径，传值保留精确端点。旧入口可保留浮点端点原编码，但未把浮点范围冒充整数 IR。编译器专用有限序列保留 break/continue/return，没有因此增加通用动态迭代框架。测试：LoopIRTest、RangeIRTest、ScopeIRTest。

| 入口 | FloatProviders、MCFloat、NumericConversions | LegacyFloatCommands、LegacyFloatComparison、捆绑数学资源 |

旧后端修复包含分量编码、有符号比较、指数缩放、零规范、8 位十进制有效数字截断、加减保护位、乘除精度及右操作数只读。常量 codec 的 nearest/ties-to-even 与运行期转换/算术截断是不同规则，不能用宿主 Float 强转抹平。旧零除按当前合同规范为四零，不假定 IEEE Infinity/NaN。

26.3 折叠和运行期保持提供器求值顺序；已知非有限输入诊断，安全读取处理非有限运算结果。详见 [浮点后端记录](float-providers-26.3.md) 与 [转换合同](type-system/conversions.md)。

### 7.2 转换与编码

### 9.2 构造与 super

ConstructorPlan 为顶层构造建立唯一 receiver 和父优先计划，每个规范 owner 的本地字段初值、所选构造体各执行一次，再进入子阶段。共享祖先在菱形中不重复。父 x=1、父体改 x=7，空子最终为 7；若子有显式 x=9，最终为 9。无显式初值的子字段不会额外清零父状态。

初值在原声明权限/import 环境下绑定，在同一 receiver 执行。祖先选择唯一可访问空实参构造，可用现有默认参数；无声明构造的普通/抽象祖先有隐式空阶段。没有父构造实参委托语法，必须额外传参会诊断，不从子参数名字猜值。

super 以当前方法的声明 owner 为锚，从直接父集合用同一候选规则查询，共享实际 this。单父可用，多无关同签名实现仍歧义；未新增 C3、动态分派或按父顺序任选实现。

## 10. 工作区新增的 MNI 体系

### 10.1 既有原生入口与新宏

既有 @MNIFunction / NativeCallContext 是编译器调用宿主实现的通路；新 @MNIMacro 让 Java/Kotlin 在编译期构造 MCFPP 代码树，展开的程序在运行期执行。旧 ABI 保留兼容分支，ValueWrapper 为旧 provider 重新出现；NativeSignatureValidator 与 Kotlin 兼容测试保护边界。历史桥退役不能扩大解释为删除所有旧 provider。

公共 API 在 top.mcfpp.mni.api，注解在 top.mcfpp.annotations。入口文件：Code、CodeBuilder、Quote、Inputs、Types、MacroContext、MinecraftBuilder、Declarations、KotlinDsl。

| 能力 | 合同 |
|---|---|
| 注册 | 工程 jars + 文件开头 injectedBy，入口 public static、首参精确 MacroContext |
| 返回 | MCFPP void 宏返回 Block，非 void 返回 Expr<T>；不是要求 JVM 返回 void |
| Kotlin | 顶层 facade 自带静态方法；object/companion 用 @JvmStatic，可用 @file:JvmName 固定 facade |
| VALUE | 源码顺序求值一次，读取稳定结果；即使宏未用也保留实参副作用 |
| REF | 显式 ref，原可写位置、精确类型、不隐式转换；允许别名，拒绝临时值/普通访问器属性 |
| CONST | 闭合常量证明，不执行普通函数/旧 MNI，失败不回退 VALUE |
| INLINE | 直接 lambda / 静态源码函数，每次插入有独立局部与 return 区，捕获原位置 |
| 上下文 | executeAs/at/rotated 与 score/NBT/位置/旋转/方块句柄 |
| 声明处理器 | annotation 全声明屏障后原子新增允许方法、内部函数及白名单元数据 |

宏与普通函数共享可见候选和类型排名；参数模式、返回类型、JVM wrapper 不区分重载。同名同 MCFPP 参数类型冲突在准备阶段诊断。作者使用结构化只读视图/builder，不接触 ANTLR、当前 Function、可变 Var 或原始命令字符串，公共树不保存宿主 lambda。

### 10.2 真实生产调用链

[MacroCallPipeline](../src/main/kotlin/top/mcfpp/mni/expand/MacroCallPipeline.kt) 是 namespace 源码宏统一入口。PrimitiveCompiler 纯识别名字后回到普通编译路径，ExprVisitor 在访问实参前进入完整宏管线。

```text
纯识别潜在宏
 → CompilerBindingEnvironment / CompilerSourceIndex
     冻结词法环境、准备全候选签名、必要时完成泛型声明
     完成后重建完整类型域并重新绑定原调用
 → SnapshotSourceCodeBinder：SourceCall / BoundExpr / BoundLocation
 → CompilerSourceBindings / SourceCodeProjector：值序言与地址捕获
 → MacroExpander：运行 provider 构造树，展开嵌套宏和 INLINE
 → CodeValidator / ContextValidator：类型、作用域、所有权和能力
 → CodeLowerer：脱离 compiler 对象的 LoweringPlan
 → CompilerBridge / CompilerPlan*：实际目标、位置、字符串和命令
 → ExpansionSession.complete / CompilerCommitBackend：提交或整体回滚
```

源码建议依次读 BoundSource/BindingEnvironment/SourceCodeBinder → DeclarationLexicalSnapshot/TypeSyntaxResolver/SignaturePreparation/PreparedTemplateHeaderReader → CompilerDeclarationPreparation/GenericDataTemplate → SourceCodeProjector/CodeArena/DefaultCodeBuilder → Inline/MacroExpander/Context* → LoweringPlan/CodeLowerer/CompilerBridge/CompilerPlan* → ExpansionSession/CompilerTransaction/各 StateJournal。

### 10.3 后续修改最容易破坏的边界

纯准备不能为取得类型执行 getter、普通/native 函数、函数体或用户初值。首次泛型可以准备受控 header，注解和真实成员 materialization 在明确外部声明阶段进行；随后重建完整域，不能旧 BoundCall 配新目标表。

VALUE 序言按源码顺序只执行一次，REF 捕获地址而非复制内容，动态下标与上下文属于地址。默认值/readonly 用原声明 formal/free 身份，不能按调用者名字补找；回调 return 只退出局部区域。

失败恢复必须覆盖准备、展开、资源/helper/名字与命令提交，不能只撤销命令。Project、Namespace、Scope、Function、Storage、声明和类型私有状态有专门 journal；要避免半个泛型实例、重复注解或耗掉名字。

### 10.4 字符串和当前能力边界

CompilerPlanStrings 等实现 string + string 精确拼接，保留 UTF-16 code unit、引号、反斜杠、控制字符、中文和 emoji。escaping helper 避免 SNBT 插值重解释，字面量 $(...) 保持原文本。MniRuntimeStringTest 与独立字符串 DSB 是历史证据。原先含换行 matcher 失败属于测试执行器识别问题。

- API 为 0.1.0-experimental，没有新增 MCFPP comptime/quote/splice、任意编译期解释器、任意运行时闭包、逃逸/延迟回调、成员宏或宏泛型。
- 当前 SourceCodeBinder literal 分支接受 null、bool、int32、float、普通行字符串；其他形态诊断 `Only closed scalar literals have source binding in this stage`。准备层/模型可表示 record/sequence，不代表所有动态集合、插值和复合源码字面量已可投影。
- 参数默认值仍按既有 `= value` grammar，没有新增任意 expression default；模型级前序表达式示例不能当作源码语法。
- 字段/索引能力依冻结 schema 和调用者权限，普通属性不能伪装可写 REF。
- projection/signature 契约仍有“尚未实现”的旧开头，当前 CompilerBridge、SignaturePreparation 等已存在；也不能仅凭 V01 设计存在就宣布非闭合复合值投影完成。

### 10.5 配置、调试和示例

macroExpansion 默认 maxDepth=64、maxNodes=100000、dump=false，每次编译独立预算。CLI：-macroMaxDepth、-macroMaxNodes、-dumpMacroExpansion[=true|false]；非法正整数、溢出和布尔值诊断；JSON 和本次 CLI 覆盖合并，避免跨调用残留。

[教程](mni/tutorial.md) 的 damage 展示 VALUE/REF，repeat 展示 INLINE/局部 return，raycast 展示 CONST 与上下文，nbt-reference 展示原字段/列表位置，score-mapping 展示 annotation 生成 load/save。各有 Java/Kotlin provider；examples/kotlin-mni 另覆盖 facade/object/companion。

示例在自身目录运行，相对路径依当前工作目录解析；injectedBy 位于开头，遇第一条普通源码/注释后不再继续读取后续指令。
