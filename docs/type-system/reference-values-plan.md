# ScoreRef / NBTRef<T> 实施提案

日期：2026-10-26。状态：提案 revision 3 已批准，实施与验证进行中；用法见 [引用值](./reference-values.md)。

## 1. 用户已经确认的结果与范围

1. 移除公开调用语法 `ref expression`，以 `ScoreRef` 和 `NBTRef<T>` 表达引用。
2. 第一版实现完整运行期引用值：可以赋值、作为普通函数参数和返回值、放入 data 字段及容器；静态已知地址直接优化。
3. 只从显式 Minecraft 地址创建引用。普通局部变量不开放取地址；原 `damage(ref local, ...)` 需要迁移到显式地址。
4. 同时支持具体实体与目标选择器。复用已经完成的 entity 设计：普通 entity 保存访问表达式及捕获的参数，在消费时查询；玩家名和 UUID 使用既有显式工厂。数量、玩家和种类限制沿用现有消费者规则。本次不重新设计多目标匹配、汇总或选择规则。
5. `target.score["hp"]` 直接产生 `ScoreRef`，`target.dat.air` 直接产生 `NBTRef<short>`。它们可保存和传递；读取沿用同步 `tryRead`，写入提供 `set`。
6. `NBTRef<T>` 的外部载荷布局由调用方保证。编译器检查写入值的类型；`tryRead` 报告实际读取是否成功，不增加针对 T 的递归运行期结构验证。
7. 减少重复测试和构建。依据实际工作区与相关输入复用证据；通过检查后，仅因相关修改、失败或具体证据缺口补验。

## 3. 建议采用的公开行为

### 3.1 类型与复制

- `ScoreRef` 指向计分项中的分数，成功读取得到 int。
- `NBTRef<T>` 指向具有既有可存储布局的 T；T 必须满足当前运行期值存储规则。
- 两种类型具有独立语言身份。普通 int / T 不隐式成为引用；ScoreRef 与 NBTRef<int> 不隐式互转。
- 可读写 NBTRef<T> 不变。NBTRef<Child> 不因 Child 可赋给 Parent 而成为可整体写入的 NBTRef<Parent>。
- 引用赋值复制地址描述，两个副本仍访问同一地址。`r = other` 更换 r 的描述；`r.set(value)` 写入目标。
- `const r` 限制 r 的重赋，目标仍按原有写入权限可写。
- tryRead 回调得到普通值快照。之后修改这个值不自动写回引用目标。

### 3.2 创建入口

已确认的实体入口：

```mcfpp
var hp: ScoreRef = target.score["hp"]
var air: NBTRef<short> = target.dat.air
hp.tryRead { value ->
    hp.set(value - 1)
}
```

其余显式地址采用普通工厂调用，不新增取地址语法。建议 API 形状如下，确切声明沿用现有标准库泛型和命名习惯：

- `scoreRef(holder, objective)`：固定 scoreboard holder，例如假玩家；实体目标使用 `target.score[objective]`。
- `nbtStorageRef<T>(storageId, path)`：命名存储。
- `nbtEntityRef<T>(target, path)`：已有 entity 目标与显式 NBT 路径；有 schema 的字段优先使用 `target.dat.field`。
- `nbtBlockRef<T>(dimension, x, y, z, path)`：建议使用明确维度和绝对方块坐标，保存后具有明确地址。相对坐标解析不在该工厂内隐式引入；这一工厂形状随本稿审阅。

地址参数按现有从左到右顺序求值一次，并复制到引用描述。随后修改 objective、路径、索引或实体工厂的源变量，不改变已经构造的描述。选择器仍在每次操作时按现有 entity 合同查询；捕获参数不等于捕获实体集合。

字段与索引投影从已有 NBT 地址派生新引用，例如 `target.dat.inventory[index]`。动态索引在创建该引用时捕获一次；引用保存的是路径，容器内容或顺序变化后沿同一路径访问，不承诺追踪原来的元素身份。

### 3.3 读写合同

- 两种引用统一使用 `tryRead { value -> ... }`，返回 bool。复用已批准的同步回调合同和现有 lambda 语义。
- 每次操作只做一次实际读取。存在且值为零仍成功；读取失败不调用正文，不返回旧临时槽内容。
- 建议 `set(value)` 返回 void，保持当前地址写入语义；不增加写入结果汇总协议。
- set 的参数按 T / int 的普通赋值与转换规则检查。不能为通过检查修改引用的目标类型。
- 保留 `target.dat.field = value`、`target.score[objective] = value` 这类显式地址写入用法，将其接到同一写入后端。`var r = target.dat.field; r = otherRef` 则按普通引用变量赋值处理。
- 原有实体消费者的数量、玩家和种类限制继续使用现有事实与诊断。引用值不能虚构单目标证明，也不能绕过这些规则。新普通调用和容器路径必须传递可保留的目标信息；不能以只支持编译期地址代替本稿的运行期引用要求。
- 外部布局不符合 T 属于调用方违反约定，不承诺 tryRead 为此返回 false；读取命令是否成功与完整类型验证是两个不同保证。

### 3.4 上下文来源

普通 entity 目标、名字、UUID 按现有访问语义进入引用描述。由 `ctx.executor` 等受借用限制的目标派生的引用必须保留来源和作用域约束：允许活跃同步作用域内使用和传递，逃出作用域时诊断。包装为 ScoreRef / NBTRef、放入 object / any 或再包装成 data 都不能消除原有借用限制。

本稿的可保存、返回及容器化要求适用于合法可保存的地址描述。新的引用类型不自动交付公共持久上下文指针或临时实体生命周期功能。

## 4. 内部实现方式

### 4.1 运行期载荷与静态信息

为引用建立明确的运行期 NBT 描述及编译期地址信息：

- Score：目标种类、固定 holder 或 entity 访问描述、objective。
- NBT：来源种类、storage 标识 / entity 访问描述 / 维度和方块坐标、路径描述。
- NBTRef 的 T 由语言类型身份维护；不为读取外部数据新增运行期类型标签。
- 路径和目标参数必须成为引用自身拥有的载荷，不能保存指向调用者临时槽或已退出调用帧的间接地址。
- 运行期分支选择引用、从函数返回引用、从 data / list 取出引用后，仍能使用相应描述。实际实现需要覆盖这种未知于编译期的载荷。
- 静态地址可保留为编译器已知信息，并直接生成目标命令；物化与优化前后行为相同。

复用现有类型注册、泛型身份、普通 NBT 值复制和库描述机制。源表示为独立的引用值适配器；公共引用类型不通过继承 int / 普通 T 获得隐式解引用。

### 4.2 统一访问入口

建立一个处理“引用描述 → 目标地址 → 读取 / 写入”的入口，供普通源函数、tryRead、地址赋值及 MNI 使用：

1. 捕获接收者、地址参数和写入值，保持已有求值顺序。
2. 静态已知描述直接使用现有命令构造；运行期描述使用现有宏参数、目标编码与必要的来源分派。
3. 目标数量与执行上下文规则交给现有实体消费者合同；不在不同入口重新实现选择器规则。
4. 读取复用成功标志和槽清理；写入接入现有存储同步与效果失效机制。动态目标无法精确定位别名时采用已有保守失效方式，避免缓存旧值。
5. 字符串和路径沿用结构化编码，保留含点、引号和反斜杠的键语义；不能把数据值当作无约束命令拼接片段。

### 4.3 普通调用、MNI 与旧语法

- 普通函数 ABI 传递引用描述本身，返回及容器取出后仍指向相同显式地址；不复制目标内容到形参区再回写。
- MNI 使用公共引用类型作为正常的类型化值，通过统一入口生成读写。旧 `REF int` 形参不能把 ScoreRef 静默当成 int。
- 编译器内部 `Ref<T>`、地址捕获、生成 helper 所需的位置能力可保留，避免无意义地重写内部模型。
- 移除公开 `ref expression` 成功编译路径；旧调用给出定位明确的迁移诊断。迁移本仓库的 damage / NBT 示例与使用该语法的相关源级测试。
- 与旧 ref 无关的 lambda、上下文和内部位置单测保持其验收目标；只调整确实依赖旧源语法的夹具。
- 同步实际使用的文档、语法副本与语言工具识别。编辑器相关验收限定于新类型/方法识别及旧 ref 的诊断；现有打包方式按实际改动运行必要检查。
