# 统一实现的维护接点

固定范围与验收只有一份，见 [续接记录](./session-continuation-2026-10-04.md)。本文件不复制或缩减固定清单，只记录后续修改必须沿用的接点；是否完成以续接记录中的实际构建、逐项验证和本地提交证据为准。

整体复用 `ValueRef`、`CompilerValue`、`Place`、`Location`、`FlowFacts` 与现有轻量 IR。表达式、控制流和调用必须使用同一声明、读写、捕获、视图、物化与效果接口；不能在 visitor 或适配器中新增第二套值事实。UnifiedValueContractTest 的验收保持有效。

- 声明与类型：沿用 `MCFPPType.resolveTypeId` 与 `tryResolve` 的声明解析机制，容器实参与泛型实参一并解析；库恢复后的声明身份必须指向真实声明。公共签名与实际载荷分开，访问布局消费当前 StoredData 的绑定类型描述，不新增全局类型对象注册表或按显示名猜测。
- 值与存储：`StorageAccess` 的 `ensure`/`read`/`write`/`view`/`element` 与 `StoredData` 的 `facts`/`types`/`declarations` 共同提供权威存储与事实接口。未赋值与可能已赋值分开；调用实参与活跃值使用独立捕获位置；视图保留来源位置，普通复制建立独立位置。未知字典访问的布局证据由同一 `readAccess` 消费，不给源键补存在性或持久初始化事实；递归字段按实际路径处理，显式状态保持严格。
- 调用与效果：调用帧和返回捕获沿用统一存储接口，`EffectAnalysis` 汇总并映射真实 receiver 和参数效果。未知效果只撤销可能变化的事实和重叠缓存，纯调用不失效事实；字面 say 的有限只读观察按现有分类处理。原生注册只发布单 NativeCallContext 签名，普通实参不加入常量特化键。
- 后端与数值：两个浮点后端按目标能力选择，不猜测未知版本、不重排浮点求值顺序；能力限制保持 [转换合同](./conversions.md) 的明确诊断，不用常量专用实现代替运行时支持。

新增能力前先核对 [已确认合同](./session-handoff-2026-10-04.md) 与用户设计决策，未确认的语法或语义不进入实现。构建统一运行，运行期间源码与测试冻结；通过验证的批次本地提交，不推送。
