# MCFPP 类型规范（重构目标与实现边界）

此文档描述类型系统的语义合同；后端能力限制以 [转换合同](./conversions.md) 的明确诊断为准。
类型组合与工厂改动的集成状态、实际执行的验证和未完成项见 [实施记录](./composition-implementation.md)；本文不表示这些检查已经通过。

## 类型身份

显示名不参与类型身份。内建类型有固定 TypeId；模板、接口和枚举采用类别、命名空间与声明名。
泛型实例的身份包含构造器及全部参数。对象类型由字段名、字段类型及可选性决定，字段初值与函数不参与身份。
交叉与联合展开嵌套、去重并规范排序；联合移除已被更宽分支包含的候选。`A & B` 具有交换、结合和幂等语义。
语言不提供 `T!` 类型后缀。类型值只能作为泛型参数声明，例如 `data Box<T>`；普通值声明 `var t: type = int` 非法。所有 `const` 声明必须带有完整编译期初值，并保护其全部后代位置；readonly 泛型绑定同样要求完整编译期快照。关闭常量折叠不改变声明是否合法。
别名解析后透明地使用被指向类型的身份。
未解析类型、泛型占位符、void 和内部静态成员视图不属于普通值类型。

声明使用 `var name: Type`，参数和字段也用冒号；`const`、`external` 声明不加 `var`，导入变量仍用 `import var`。readonly `<T>` 等价于 `<T: type>`，值参数使用 `<N: int>`；普通参数必须使用 `name: Type` 声明显式名称。
`if`、`else if`、`while`、`do ... while` 的条件括号可省略，条件须为 `bool`。语句用换行或分号分隔，块内最后一条语句无需分号；同一行语句间和 SNBT 数组内的分号保留。

## object、any 与 DataObject

object 是统一静态超类型。int、float、bool、string、NBT 映射类型、集合、模板、any 及非 type 编译器载荷均可向上解释为 object；TypeValue 不能借 object/any 绕过普通值位置限制。
object 的成员由其公共签名决定，知道来源类型不会增加其成员。
any 是擦除类型：实际类型唯一已知时使用该类型绑定操作；未知或有多个候选时，具体操作须显式 as。不引入运行时类型标签或自动分派。
DataObject 仍是数据模板基类，位于 object 下；nbt 表示原始 NBT，不是所有可编码类型的父类。
内部静态成员访问对象名为 StaticMemberView。

## 隐式转换与重载

查询从实参类型指向形参类型；查询本身不能生成命令或修改变量。
int 可以提升到 float，反方向不允许隐式转换。
NBT byte / short / long / double 不继承普通 int / float 算术语义；bool 的 ByteTag 编码不改变类型身份。
泛型声明支持 `<out T>` / `<in T>`，未标注时不变；方差依据子类型关系并检查嵌套输入/输出位置，不沿用数值提升，也不提供语言星投影。可变容器参数保持不变；ImmutableList 使用只读列表接口，但该内建类型仍保持泛型不变，不因只读接口自动增加协变转换。
重载按精确匹配、子类型兼容、int 到 float 提升、object、any 排序；同级选择最具体候选，否则报歧义。
缺省实参只在对应参数声明默认值时省略；单一候选也必须验证实参。

## 对象合同与类型组合

`{ x: int, y: string }` 是对象类型；`{ x: 1, y: "ok" }` 是对象值。对象合同开放：来源可以包含目标未要求的额外字段，目标的必需字段必须存在；可选字段允许缺失，存在时必须满足字段类型。初始化、赋值、参数、接收者、返回和泛型约束使用同一个结构子类型关系。

对象字面量支持词法简写 `{ x }`，等价于 `{ x: x }`，也支持空对象 `{}`。重复字段报错，带引号的键先解码再比较，因此 `x` 与 `"x"` 重复。对象展开未开放。已有明确 `dict<T>` 上下文仍生成字典；无上下文的对象字面量推断字段合同。

空花括号和单个名称花括号在函数类型上下文中保留 lambda 含义，例如 `(int) -> int` 的 `{ it }`。其他值上下文中的 `{ x }` 读取词法变量 `x` 并生成对象字段。

readonly 类型实参可写作 `Box<{ x: int }>`；这种位置的显式标识符字段须全部给出类型。空的 `Box<{}>` 仅在对应 readonly 形参为 `type` 时表示空对象类型，普通表达式中的 `{}` 仍是对象值。

编译期已知的基本值有内部字面量类型：`1 <: int`、`"ok" <: string`、`true <: bool`。`const x = 1` 的类型是 `1`；普通可变目标拓宽相应字面量类型。数值字面量类型目前没有独立的用户类型语法。

类型位置使用 `(A & B)` 和 `(A | B)`。交叉要求同时满足所有合同；同名字段的类型取交叉，任一来源要求字段存在时，合并字段必需存在。必需字段交叉为 `never` 时，整体为 `never`；可选字段交叉为 `never` 时，字段只能缺失。联合只允许访问每个分支都保证的成员，读取保留所有可能类型，写入同时满足每个分支的约束。

`data A : B, C` 的数据合同是父合同与本地字段的交叉，字段扁平化为一个存储布局。同源菱形路径去重；兼容的同名普通字段合并。继承声明额外拒绝普通字段与 const 字段同名，无论父声明顺序如何；普通交叉继续计算字段类型约束。

模板体内的普通实例函数保留 `this`，按带接收者的自由函数处理。数据继承不复制、覆盖或自动暴露父函数；接收者兼容性按普通子类型合同检查。源码 `super` 不再表示成员或构造分派。

## 值与数据位置

Symbol 保存声明身份、声明类型与约束；Place 保存底层位置和字段或索引路径。Location 同时保留求值时捕获的下标、键、调用帧和实体来源。
ValueRef 与 TypedView 不拥有新的数据身份。as 保留来源位置与来源声明约束；普通复制建立独立位置，声明别名不重新初始化来源。
公共声明类型决定成员、重载与访问权限；实际载荷和生产者布局决定捕获、复制及编码。object 不因已知来源而获得额外成员，编译器专用载荷不因擦除为 object/any 而获得运行时布局。普通调用按实际载荷绑定，不按普通实参的常量组合特化，也不改变公共参数和返回契约。
类型信息 Exact / Candidates / Unknown 与值信息 Constant / Partial / Program / Unknown 独立。CompilerValue 是不可变的完整载荷；Selector 的有限 Program 可以包含已捕获运行时操作数，因此不能作为 readonly 泛型的完整编译期实参。
值状态 UNINITIALIZED、MAYBE_INITIALIZED、INITIALIZED 和 ERROR 分别表示未赋值、部分路径已赋值、已赋值和错误；不可达由控制流可达性表示。字段存在性 Present / Absent / Unknown 独立于初始化状态。可选字段可以合法缺失；常量载荷不可引用可变 Var 或 NBT Tag。
external 要求可用的运行时表示；物化保留已证明的类型、值和形状事实。运行期运算仍须发射真实命令，不能用保留的事实代替执行。写入失效重叠位置和存储缓存；动态索引保守地覆盖潜在元素。
控制流汇合只保留所有可达前驱共有的信息；循环通过保守不动点求解。const 首次赋值要求所有可达前驱均证明该位置未赋值，Unknown 或 MAYBE_INITIALIZED 不构成证明；每次进入循环局部声明开始新的声明生命周期。
const 和 readonly 约束均覆盖内容与后代，包括字段、索引、集合操作、setter、删除和可能覆盖常量子树的整体写入。写入同时检查访问声明和来源声明；非法写入不提交值事实或调用写回效果。const 值复制到独立 var 后，其普通字段可以修改，模板固有 const 字段继续受保护。
未知字典的具体键访问可消费已绑定元素类型的可读布局，但类型证据不证明键存在。访问局部的字段证据通过同一事实接口读取；实际复制或返回可将证据传给独立目标，不能据此给源键新增持久 INITIALIZED、常量或长度事实。递归布局按实际访问路径处理，显式 UNINITIALIZED、MAYBE_INITIALIZED 和 ERROR 不得被声明布局覆盖。

## as 与转换函数

as 产生与来源共享 Place 的临时解释视图，不调用构造器、不补字段、不转换数值。临时视图赋值给变量（包括声明初始化）时，按普通值赋值复制载荷到目标的独立 Place；修改目标内容不影响来源。显式 Ref 系列值的复制保留其引用目标。
名义关系可用于普通来源的警告；any 来源不进行运行时类型检查。结构形状不兼容不构成对 `as` 的拒绝。
目标没有可用的存储访问方式时给代码生成错误，并建议转换函数。
数值转换使用 toInt / toFloat / toByte / toShort / toLong / toDouble；toNBT 生成来源约定的编码。
常量转换与运行时后端遵守相同规则；无法证明等价时不得用宿主强转折叠。
共享位置上的写入同时满足视图合同、真实存储合同和 const 约束；`as` 不放宽真实位置的写权限。

## data 成员、存在性与子模板

`data` 的 const 字段在声明完成或泛型绑定后取得固定值，其合同使用相应字面量类型。显式对象字面量必须自己提供完整字段，包括匹配的 const 字段；目标类型不会自动补值。通过父类型或 as 访问时，以实际来源的字段值和保护约束为准，不能用视图声明的值替换真实载荷。

```mcfpp
data Packet {
    const schema: int = 2 + 3
    var count: int { get }
    var label: string?
    var doubled: int { get = this.count * 2 }
    new(initial: int) { return { schema: 5, count: initial } }
    data Item { var id: int }
}
func consume(item: Packet.Item): int { return item.id; }
```

普通字段默认可读写；`{ get }` 是有后备位置的运行时只读属性；`{ get = expression }` 或 `{ get { ... } }` 可定义计算 getter，`{ get; set }` 与显式 setter 定义读写能力。成员的 `public` / `protected` / `private` 修饰符控制其访问权限；`protected` 权限依据声明归属与名义继承关系判断，结构兼容不授予成员访问权限。只提供 getter 不意味着编译期常量。

模板字段的 `var label: string?` 表示字段可缺失，不表示值可以为 `null`。对象字面量省略该字段即可；`{ label: null }` 不满足它。此可选语法只开放给模板字段，不是普通局部变量、参数或返回类型的通用构造器。显式声明 getter 或 setter 的字段不能使用 `T?`，包括 `{ get }`、`{ set }` 和自定义访问器。

`obj.x != null` / `obj.x == null` 直接检查后备位置存在或缺失；`obj.x = null` 删除可选字段。必需字段始终要求存在，不能删除。零值、空串和空容器都表示字段存在。重复删除合法；删除常量后代非法。读取可选字段需要存在证据，删除和相关调用写效果使该证据失效，分支合流只保留共同事实。纯计算属性不支持位置存在性或删除。`null` 仅用于删除和存在性检查，不能传给函数（包括 `any`、`object` 和原生函数的参数），也不能存入变量、容器或作为返回值。

可选字段支持以下表达式操作：

| 写法 | 行为 |
| --- | --- |
| `obj.child?.name` / `obj.child?.method(args)` | 接收位置缺失时跳过选择、实参和调用；存在时执行一次。结果仍可能缺失。 |
| `obj.value ?: fallback` | 存在时取左值；缺失时才计算右式。`0`、`false`、空串和空容器不会触发右式。 |
| `obj.value!!` | 由程序员保证存在，直接读取；不生成存在性检查、异常或默认值，也不建立后续读取的存在证明。 |
| `obj.child?.value = rhs` | 中间接收位置缺失时跳过整个赋值及 `rhs`。最终字段可为必需或可选字段；删除仍要求最终字段可选。 |
| `obj.value ?: return value` / `obj.value ?: return` | 缺失时退出当前源码函数或 lambda；循环与嵌套表达式遵循同一个返回目标。 |

可能缺失的中间结果只能继续用于安全调用、Elvis、`!!`、判空或作为独立语句丢弃。存储、算术、普通实参和返回值需要先得到确定存在的值。`?.let { ... }`、`?.also { ... }` 使用现有同步 lambda；接收位置缺失时不会执行回调。

`!!` 是后缀操作，前缀 `!!flag` 仍是两次逻辑取反。`?:` 比算术运算优先级低，比比较和逻辑运算优先级高，同级从左到右结合。不支持 `?: null`、`as?` 或 `?[]`。

子模板统一公开，归属不产生继承或隐式外层实例。声明先递归注册，再完成成员签名，支持多层名称和前向引用。`Outer.Inner` 可用于字段、参数、返回、构造、泛型实参、as 和继承；导入 `Outer` 也公开其子模板。内模板的 readonly 参数按外层到内层排列，例如 `data Outer<N: int> { data Inner { const schema = N } }` 使用 `Outer.Inner<2>`，绑定值参与类型身份。源码匿名 `data { ... }` 应迁移为具名声明；内部合成与库恢复仍可使用匿名类型。

## new 工厂

模板体内的 `new(args...) { ... }` 声明所属模板类型命名空间中的普通工厂函数，返回类型为所属模板的完整类型 `Self`。工厂没有接收者，工厂体中没有 `this`；普通参数均须显式声明，调用不会添加隐藏首参数。每条可达成功路径必须显式返回满足 `Self` 的值，不采用尾表达式返回，也不预分配待逐字段赋值的对象。

`A(args...)` 使用普通重载规则解析到 `A.new(args...)`，不会自动调用父工厂。父工厂同其他工厂一样通过 `Parent.new(args...)` 显式调用，得到独立、完整的 `Parent` 值。子工厂读取该返回值的字段并组合完整的子对象；调用不会向参数列表插入子对象，也不要求调用方与工厂所属模板具有名义继承关系。

```mcfpp
data Parent {
    var x: int
    new(x: int) { return { x } }
}
data Child : Parent {
    var y: int
    new(x: int, y: int) {
        var parent = Parent.new(x)
        return { x: parent.x, y }
    }
}
```

本地字段初值可生成隐式零参数工厂：先按词法顺序计算本地初值，再返回完整对象。生成过程不采用继承字段的初值，不调用父工厂；无法满足必需字段时不生成默认工厂。空模板生成返回 `{}` 的工厂；显式零参数 `new` 替代隐式零参数工厂，其他重载并存。对象字面量和显式工厂返回之后没有额外的字段初始化阶段。

## 后端与副作用

存储包含记分板、NBT、旧浮点分量、未物化常量和编译器专用载荷。
编译器专用载荷不能通过 object 获得运行时存储能力。
语言可达原生接口只接收一个 NativeCallContext，通过同一值、位置和效果接口发布返回或写回；宿主包装器不作为语言分派后备。
未知效果的原始命令与未标注原生调用是外部状态屏障；纯调用不失效事实。有限例外为不含插值标记或换行的字面 say 命令，归为 ReadsRuntime，只观察已物化值。观察前物化，随后按实际效果撤销可能变化的事实和重叠缓存。
26.3 数值提供器后端与旧模拟后端具有各自的常量求值规则，禁止改变浮点求值顺序。

方法调用在绑定实际接收者和执行原生 provider 前检查写效果，将 this 路径映射到来源 Place。读、计算和输出允许在 const 接收者上执行；直接、间接、递归或 getter 内部写入受保护位置均拒绝。无法证明安全的效果给出接收者与方法诊断。object 的常量子树有全局身份，可变兄弟字段仍可更新；接收者整块写回按语义写范围检查。普通原生参数使用独立值副本。

库格式 v4 保存对象与字面量类型、工厂标记、常量合同及固定值、字段可选性和访问器、限定声明身份。函数源码与原生效果声明用于导入后的调用检查。v3 及更早的库须用新编译器重建，开发期 Kryo 缓存版本同时升级至 88。标准库的运行时 getter-only 用法改为 `var ... { get ... }`。
