# MCFPP 类型规范（重构目标与实现边界）

此文档描述本次重构的目标语义。具体已接入的范围见 migration.md；尚未接入的规则不能作为当前编译器的承诺。

## 类型身份

显示名不参与类型身份。内建类型有固定 TypeId；模板、接口和枚举采用类别、命名空间与声明名。
泛型实例的身份包含构造器及全部参数。联合类型去重、展开嵌套并规范排序。
语言不提供 `T!` 类型后缀。类型值只能作为泛型参数声明，例如 `data T<t as type>`；普通值声明 `x as type=int` 非法。`const` 只限制重赋，不要求初始化值在编译期已知；readonly 泛型绑定仍要求完整编译期快照。
别名解析后透明地使用被指向类型的身份。
未解析类型、泛型占位符、void 和内部静态成员视图不属于普通值类型。

## object、any 与 DataObject

object 是统一静态超类型。int、float、bool、string、NBT 映射类型、集合、模板、any 及非 type 编译器载荷均可向上解释为 object；TypeValue 不能借 object/any 绕过普通值位置限制。
object 的成员由其公共签名决定，知道来源类型不会增加其成员。
any 是擦除类型：已知实际类型时使用实际类型绑定操作；未知时只能传递给 any 或 object，具体操作须显式 as。
DataObject 仍是数据模板基类，位于 object 下；nbt 表示原始 NBT，不是所有可编码类型的父类。
内部静态成员访问对象名为 StaticMemberView。

## 隐式转换与重载

查询从实参类型指向形参类型；查询本身不能生成命令或修改变量。
int 可以提升到 float，反方向不允许隐式转换。
NBT byte / short / long / double 不继承普通 int / float 算术语义；bool 的 ByteTag 编码不改变类型身份。
可变容器参数不变。ImmutableList 使用只读列表接口；当前类型关系同样保留泛型不变策略，尚未引入协变转换。
重载按精确匹配、名义父类型、int 到 float 提升、object、any 排序；同级选择最具体候选，否则报歧义。
缺省实参只在对应参数声明默认值时省略；单一候选也必须验证实参。

## 值与数据位置

Symbol 保存声明身份、声明类型与约束；Place 保存底层位置和字段或索引路径。
ValueRef 与 TypedView 不拥有新的数据身份。
类型信息 Exact / Candidates / Unknown 与值信息 Constant / Partial / Unknown 独立。
未初始化、错误和不可达为不同状态。常量载荷不可引用可变 Var 或 NBT Tag。
物化不清除常量事实。写入失效重叠位置和存储缓存；动态索引保守地覆盖潜在元素。
控制流汇合只保留所有可达前驱共有的信息；循环通过保守不动点求解。

## as 与转换函数（待端到端迁移）

as 建立同一 Place 上的解释视图，不调用构造器、不补字段、不复制对象、不转换数值。
不兼容的普通来源给警告；any 来源不进行运行时类型检查。
目标没有可用的存储访问方式时给代码生成错误，并建议转换函数。
数值转换使用 toInt / toFloat / toByte / toShort / toLong / toDouble；toNBT 生成来源约定的编码。
常量转换与运行时后端遵守相同规则；无法证明等价时不得用宿主强转折叠。
结构形状只决定重解释是否需要警告，不产生隐式模板子类型关系。

## 后端与副作用（待完整接入）

存储包含记分板、NBT、旧浮点分量、未物化常量和编译器专用载荷。
编译器专用载荷不能通过 object 获得运行时存储能力。
原始命令与未标注原生调用是外部状态屏障；纯调用不失效事实。
26.3 数值提供器后端与旧模拟后端具有各自的常量求值规则，禁止改变浮点求值顺序。
