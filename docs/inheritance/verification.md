# data 继承修复验收记录

本文把[原审查记录](../../build/inheritance-review/README.md)中的 12 个具名探针和字段共享问题逐项对应到当前实现、正式测试及已保存的运行结果。原探针是旧行为的复现材料；它们通过只能证明缺陷曾经出现，不能证明当前语义正确。当前预期行为以[实现契约](implementation-contract.md)为准。

本文保留 13 项问题映射和之前轮次的 199 项 fresh 往返、schema 80 再生及早期批次记录，并把它们明确标为历史证据。当前最终功能状态以 [MNI 回归结果](../mni/regression-results.md) 中的全量运行 + 受影响定向运行报告为准；历史证据不替代该合并结论。

## 语义选择

- 字段仍按名称提供一个有效存储槽。相同 canonical 字段经菱形继承只保留一份；来自无关父类型且契约兼容的同名字段，在没有本地声明时报告歧义。子类可以用兼容的本地声明明确合并；合并后保留子声明自己的 `Var`、初值、访问器、`const`、注解和 owner。类型、nullable、静态性、const 或访问契约不兼容时报告冲突，不能靠父顺序或本地字段掩盖。
- 构造按唯一 canonical owner 生成父优先计划。每个祖先阶段执行该 owner 的字段初值和所选构造体一次，再进入派生 owner；子本地初值因此覆盖父阶段的值。相同绑定的泛型祖先去重，不同绑定仍是不同阶段。
- `super` 从当前方法声明 owner 的直接父集合查询，继续使用全候选排序和最具体 owner 规则，并共享同一实际 receiver。仍有多个无关实现时报告歧义，不按父列表位置任选一个，也不绑定到复制的父对象。

这些是本轮实现采用的兼容和安全语义，不表示原报告曾替语言规范作出决定。未引入 C3、动态分派或新的父构造委托语法。

## 泛型、fresh `.mclib` 与运行边界
