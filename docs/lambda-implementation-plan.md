## 2. 用户能使用的功能

```mcfpp
var add = { a: int, b: int -> a + b };
var value = add(2, 3);

items.map { item -> item + 1 };
items.filter { it > 0 };
items.fold(0) { sum, item -> sum + item };

var action = {
    print("Hello");
};
```

交付普通函数引用、可书写函数类型、lambda 赋值/传参/调用/返回、创建时捕获、闭包重复调用与复制、同签名动态目标选择、嵌套闭包，以及同步 map/filter/fold/foreach 的可运行示例。高阶操作优先复用现有容器遍历能力，只补与这些示例直接相关的接口。

普通 lambda 的内联与非内联形式必须保持捕获和控制流语义。实际执行使用调用点的 Minecraft 执行上下文，不隐式冻结创建处的 @s、位置或维度。

暂缓：暂停和 generator 的执行引擎、await/spawn/yield、Result API、异常传播、capture(ref ...)、闭包作为容器元素、长期持久化/跨 reload 恢复、任意字符串转可调用地址、共享可变局部盒与 GC。函数值的执行类别必须保留；普通 lambda 不因目标类型或体内操作自动获得暂停或产出能力。本期对尚未支持的类别给出明确诊断。ScoreRef/NBTRef 等引用捕获暂不实现。

## 3. 语法与类型实施约定

### 3.1 Lambda 和尾实参

- 形状为 { a: int, b: int -> body }；目标签名明确时可写 { a, b -> body }。
- 最后一个实参可移到调用括号外；唯一实参为 lambda 时可省略调用括号。
- 无参数可写 { body }。
- 无参数列表且目标明确为单参数函数时引入 it；没有目标类型时按零参数 lambda 处理，未绑定 it 报错。不能仅靠 it 的使用猜测未知参数类型。
- it 按词法作用域绑定；内层单参数隐式 lambda 遮蔽外层 it；零参数或显式命名参数的内层 lambda 不自动声明 it，仍可按普通捕获规则访问外层绑定。无法唯一确定目标签名时报告推导/重载歧义。
- 语句块、现有 NBT/复合字面量、括号表达式、控制语句和尾 lambda 必须在真实 grammar 中消歧。新增语法不能依靠换行临时猜测调用含义。
- 类型标注统一冒号。

### 3.2 返回和控制流

- lambda 最后一个未以分号终止的表达式可贡献返回值。表达式后的尾随分号使其成为普通语句，此路径无隐式结果。
- 目标返回 void 时允许执行尾表达式并丢弃其值，保留副作用；没有目标类型时从显式 return 和尾表达式推导结果。
- 显式 return 只结束当前 lambda；嵌套 lambda 分别拥有返回区域。内联不改变返回目标。
- break/continue 只能指向当前 lambda 内词法包含的循环。
- 非 void 返回要求所有可达完成路径提供可赋值的结果；显式 return 与尾表达式不一致时报错。使用已有类型合并/可赋值规则，不能靠退化成 any 隐藏冲突。
- 不在本次扩展普通具名函数的尾表达式返回，不新增标签返回、非局部 return 或通用 if/when 表达式系统。

### 3.3 函数值类型

提议拼写为 func(int, int) -> int 和 func() -> void，作为现有 type 的一种形式；变量、参数的类型标注仍使用冒号，具名函数声明沿用当前语法。此拼写是本稿对新记录待定项的选择，不继承旧稿 throws 契约。

函数类型保留参数、结果和执行类别。兼容检查采用安全的参数逆变、结果协变，并复用现有名义子类型关系；不扩大普通对象的结构式兼容。泛型高阶函数需能从调用目标推导 lambda 参数及返回类型，重载不唯一时给出诊断。

普通函数名可以在目标签名约束下解析为函数值；重载引用必须唯一。成员方法引用必须携带接收者，并遵守同样的捕获规则。函数值调用实参按现有顺序求值且每项只求值一次。

## 4. 捕获、引用与存储

- 捕获由词法绑定身份确定，在 lambda 表达式求值时创建；不能通过之后同名变量查找替代原绑定。
- 普通值按其类型的复制契约捕获。整数等标量为创建时快照；不自动建立外层可变变量共享盒。
- 捕获绑定保持只读：在 lambda 内重新赋值或复合赋值捕获的局部值时报错，不能修改外层局部值。本期通过返回值或 fold 等显式累积结果；引用捕获留待后续。
- 全局符号继续按全局位置读取；若需冻结其值，先赋给局部值再捕获。
- ScoreRef/NBTRef 等引用捕获暂不实现。
- 没有明确复制/生命周期契约的类型给出具体捕获诊断。不能静默按位复制失效路径，也不能把所有对象都宣称为独立快照。
- 返回闭包的环境由调用者拥有；不能引用已释放或复用的函数局部槽。复制和嵌套捕获同样检查环境所有者。
- 同一构造函数创建的多个闭包必须独立保存普通值环境；普通闭包调用不消费该值。动态目标采用有限已知目标集合及相应环境布局。
- 对同步递归/重入保存受覆盖的活跃状态，复用现有可靠机制；不能以单线程为依据共用不安全槽。只在确实需要时保留状态，不进行全编译器栈重构。

## 5. 现有实现衔接

已检查的入口：
- src/main/antlr/mcfppParser.g4：当前 parameter 使用冒号；functionCall 仍以命名目标为中心；存在待迁移的 MNI inlineLambda 旧语法 (args) => { ... }。
- src/main/kotlin/top/mcfpp/antlr/MCFPPExprVisitor.kt 和 analysis/DeclarationBinding.kt：表达式、调用和类型绑定接点。
- src/main/kotlin/top/mcfpp/mni/expand/SourceCodeBinder.kt、SourceBodyBinder.kt、BoundCallback.kt：已有编译期源码回调绑定、捕获身份和返回区域；不等价于可保存环境的运行时闭包。
- src/main/kotlin/top/mcfpp/analysis/StorageAccess.kt、model/function/、type/、io/info/：调用、存储、类型和库元数据接点。
- DSB：按用户指定作为生成命令的执行验收工具，接入现有项目用法；上述源码/语义检查可复用已有单测，但不能替代 DSB 的实际执行结果。

MNI 宏由 Java/Kotlin 代码在编译期间构造 MCFPP 的运行时代码。现有 INLINE 参数接收源码回调体，只能在展开点使用，不能直接作为运行时函数值保存或返回。已有教程 docs/mni/tutorial.md §3.4 及 examples/mni/repeat/project/src/main.mcfpp 使用 repeat(5, (i) => { ... })；其中 () 是参数列表，=> 分隔参数和代码块，() => { ... } 就是零参数的旧写法。

用户已在本次聊天选择统一迁移：新的源码入口统一使用 repeat(5) { i -> ... } 或 repeat(5, { i -> ... })。MNI 的内部 INLINE 实现机制可以复用，但源码 lambda 的绑定、创建时值捕获、只读环境、尾表达式和局部 return 必须遵循本计划。由接收 API 或内联优化选择实现方式，不能改变同一 lambda 的语义。

删除旧 (args) => { ... } 源码入口，提供指向新语法的迁移诊断。迁移仓库中的宏示例、相关测试、教程及必要的源码重解析接点，不维护一套旧捕获语义。曾依赖捕获写入的 total += i 等示例改为显式返回/结果累积；不能只替换箭头后继续要求外层局部变量被修改。保留原示例有意义的输出结果和控制流覆盖，以新增负例验证捕获写入被拒绝。

动态函数值不能提供静态源码体时，仍须按接收 API 的真实能力处理：普通函数值参数走调用路径；只接受静态源码体的 INLINE 参数给出准确限制诊断。不能为了接入宏而把闭包悄悄降成引用捕获。

尽量只修改 MCFPP 编译器、必要库资源、测试和示例；VS Code 扩展、独立 linter 与编辑器展示不在当前交付要求内。保留现有未提交改动，不提交或发布仓库。

## 7. 验收边界

| 场景 | 必须观察到的结果 |
| --- | --- |
| { a: int, b: int -> a + b } | 可赋值、传参并实际调用，2 与 3 得到 5 |
| 上下文参数、it、嵌套遮蔽 | 正确绑定；缺失类型或重载歧义定位到参数/调用 |
| 无参、尾 lambda、控制块和字面量 | 正确解析；既有语法不被误吞 |
| 尾表达式/尾分号/void/分支返回 | 严格符合第 3.2 节；副作用保留，缺失返回有诊断 |
| lambda return 与循环控制 | 仅结束当前回调；外层仍继续；跨边界 break/continue 被拒绝 |
| 创建后修改外层整数 | 回调仍读创建时值；循环每次捕获独立 |
| 返回、复制与嵌套闭包 | 构造函数退出后仍正确；各环境不串值、不读失效槽 |
| 运行时选择不同闭包 | 调用正确代码和对应环境；避免只测编译期常量条件 |
| 函数/成员引用和泛型回调 | 签名匹配，接收者语义正确，参数顺序和求值次数正确 |
| 同步重入 | 必要活跃值和当前环境不被下一次调用覆盖 |
| .mclib 导出后新编译会话导入 | 签名、代码目标、环境和调用行为与源码一致 |
| MNI 与普通 lambda 统一 | 宏接收新语法且遵循相同捕获/return 规则；旧箭头语法给出迁移诊断；旧捕获写入示例改为显式结果累积，相关输出和控制流覆盖保留 |
| 普通 lambda 中的暂停/产出能力 | 明确拒绝，不通过上下文自动升级执行类别 |

语义检查必须包含真实 MCFPP 源码编译、生成命令和 DSB 实际执行断言。功能优先，不进行性能测试或手写基线成本比较。

运行受影响的语法、类型、调用、存储、MNI 和库往返检查。阶段内采用针对性检查；最终集成时运行既有完整回归一次，区分原有失败与新增回归，修复后按影响范围补验。重要的库格式/导出改动需要非作者复核。结果仅在相关源码、依赖、配置和环境未变时复用。
