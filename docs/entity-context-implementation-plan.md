# 实体变量与执行上下文 lambda 实施计划

日期：2026-10-23。状态：修订 5 已批准，工作流 `8b7cfce8-1154-4737-81a0-c30751b4a23c` 的实施交付已完成。下文保留审批时的设计与任务划分；当前用法和验证范围见 [实体值与执行上下文](entity-context.md)。

## 1. 交付目标与已确认范围

让下列源码通过正常编译入口生成并执行对应的数据包命令：

```mcfpp
var qwq = @s

qwq.withPosCtx { posCtx ->
    posCtx.onPassengers { psgCtx ->
        tp(psgCtx.executor, posCtx.pos)
    }
}
```

在当前执行者存在时，其核心行为对应：

```mcfunction
execute at @s on passengers run tp @s ~ ~ ~
```

允许编译器使用必要的辅助函数；验收比较实体目标、位置参考、分支次数和作用域退出行为，不强制整个程序只有一行命令。

已确认：
- 普通实体变量使用统一的 entity 类型，保存访问方式，在使用点的执行上下文中解析。
- 支持单目标事实推断；运行时可变的 limit 无法证明至多一个，要求用户进入逐实体作用域或明确缩小目标。
- 使用现有花括号和箭头 lambda，以及嵌套的 withPosCtx / onPassengers 调用。
- 上下文 API 的回调参数属于执行上下文类型体系，提供明确的 executor 和 pos。
- 不实现 |ctx>、|>>、独立点号等缩写模式。

当前源码的显式声明沿用 `var a: entity = @a`。

## 2. 建议采用的语义合同

以下是为形成可实施计划提出的具体选择，随本稿审阅；此前助手给出的建议不视为用户已经逐项批准。

### 2.1 普通 entity 值

- 内部目标表示至少覆盖 Selector、PlayerName、UUIDText 三种直接命令参数。名字与 UUID 文本通过明确的标准库工厂构造，不把任意字符串隐式当作选择器。
- 工厂名称建议为 `entityByName(name)` 和 `entityByUUID(uuidText)`；运行时字符串沿用现有宏能力和参数校验，不能通过命令片段拼接改变目标结构。
- 赋值、参数传递、返回和普通 lambda 捕获沿用值复制合同：复制访问表达式与构造时捕获的参数，随后修改源变量不改变副本。查询目标实体发生在消费时。
- 数量、仅玩家、已知实体种类作为事实维护，不再通过不同 entity<N> / entity<类型> 身份表示。迁移现有使用点、库元数据与诊断。
- 能证明的单实体规则必须考虑选择器自身语义及限制参数覆盖；不能只凭 @p/@r 等起始字母作无条件判断。未知宏 limit 按可能多实体处理。
- 普通函数中的未知 entity 形参不伪造单实体保证。单目标操作要求可用事实，或由 withEntityCtx 建立逐实体执行分支。
- 保留当前可表达的选择器载荷复制、普通调用和捕获。对于运行时分支导致结构无法完整表示的值给出明确诊断；本稿不承诺任意运行时字符串解释器、任意长度动态关系路径或实体集合快照。

### 2.2 执行上下文类型与分量

设置公共基类 ExecutionContext；PosContext、EntityContext、RelationContext 为具体上下文类型/子类型。最终名称可按标准库约定统一，但必须存在公共类型关系和可定位诊断。

每个上下文实例拥有唯一来源标识、词法作用域与分量来源：executor、position、rotation、dimension。需要时保留原有 anchor 状态；不在本期新增完整 execute DSL。

- 上下文只读；上下文操作创建子上下文并继承未修改分量。
- 语法嵌套记录父子实例关系，不要求每一层的具体类继承上一层的具体类。
- ctx.executor 是该上下文绑定的执行者访问，保留实体身份来源与作用域信息。它可进入实体命令参数接口，但不能在复制、擦除为 object/any 或传参时退化为当前 @s。
- ctx.pos 是绑定位置分量与维度的位置值。它不能仅被编码为无来源的 `~ ~ ~`，也不能自动改为原实体移动后的新位置。
- 空执行者保持为空；不会因为存在上下文对象就获得“目标必存在”的保证。成功进入关系回调的 executor 对应当前分支的一只实体。

### 2.3 上下文操作

| API | 执行语义 | 回调分支 |
| --- | --- | --- |
| entity.withPosCtx | 对应 execute at target；改变位置、旋转、维度，继承调用点执行者 | 每个匹配目标一个分支 |
| entity.withEntityCtx | 对应 execute as target；改变执行者，继承空间分量 | 每个匹配目标一个分支 |
| ctx.onPassengers | 沿接收上下文的执行者访问直接乘客；只改变执行者 | 每只直接乘客一个分支 |
| ctx.onVehicle / onOrigin | 沿接收上下文的执行者访问关系；只改变执行者 | 每个起点零或一个分支 |

同一关系实现扩展到 onOwner、onController、onLeasher、onTarget、onAttacker；按编译目标实际支持的关系集合注册并诊断，不扩展新的兼容版本目标。

重要区别：当 target 不是 @s 时，withPosCtx 不隐式附加 as target。因此 onPassengers 沿继承的执行者访问；想遍历 target 自己的乘客，应先调用 withEntityCtx。文档和执行用例必须覆盖此差别。

关系路径保留命令本身的分支次数；多个起点到达同一目标时不自动去重。空目标或无关系时回调不执行。

### 2.4 Lambda 与作用域

- 复用现有尾 lambda grammar、目标签名推导、词法捕获、局部 return 及语句顺序。
- 只有这些上下文 API 的回调建立新的 Minecraft 执行上下文；普通 lambda 和集合回调不因语法嵌套自动改变执行者或位置。
- 上下文回调同步执行，返回 void。尾表达式按已有 void 规则丢弃结果但保留副作用。
- return 结束当前回调，不退出外层函数；多乘客时不因某个回调 return 而跳过其他分支。break/continue 沿用已有 lambda 边界。
- 内层上下文回调可以借用仍然活跃的外层 ctx、ctx.executor、ctx.pos。它们拥有不同于普通持久闭包快照的作用域引用规则。
- 支持这些受控回调内的局部别名、嵌套调用及普通同步辅助调用；所有传递路径保留来源与作用域证据。
- 将上下文或其绑定句柄返回到外层、写入全局/容器、放入可能逃逸的闭包、延迟或跨 tick 使用时给出明确诊断。此限制不能误拒绝用户示例的内层回调引用 posCtx。
- 第一版上下文入口采用可静态绑定的同步回调正文；不承诺运行时任意函数值分派能接收作用域上下文。

### 2.5 外层句柄与命令求值

- 当前上下文保留相同分量时直接复用，例如 onPassengers 内使用外层 posCtx.pos。
- 后续层改变了相关分量时，外层引用仍保留原绑定。按需在改变前物化执行者身份或位置/维度，或生成等价的结构化命令；不能重新求值原选择器冒充原分支。
- 对同一操作中的多个目标分别保持绑定，不因内部 execute 改写其他实参中的 @s；有副作用的普通实参按现有顺序求值一次。
- 不默认保存每层所有分量。用户提供的基本示例应保持直接上下文继承的实现。
- 不把任意语句重排或提升 at 到整个回调入口；保留条件判断、世界修改和相对坐标读取的先后顺序。

## 3. 命令接口与数据访问

- 提供真实可导入的自由函数 `tp(target, position)`，让用户给出的调用原样成立；接入现有命令发射路径，不仅在测试夹具中定义此函数。
- target 接受普通 entity 与带作用域来源的 executor；position 接受已有坐标值和上下文位置值，重载不抹去来源信息。
- 迁移现有实体命令的接收者检查，至少覆盖 tp、tag、ride、实体属性以及玩家专用命令的数量/种类检查；不再将 SelectorVar 强转作为唯一入口。
- 实体 NBT 来源和现有计分板位置接口使用相同目标编码与绑定规则，避免 tp 可用但 `.dat` 或既有分数访问仍绑定错误实体。
- 普通 entity 的数据成员按可证明的实体种类提供；类型未知时使用公共成员，具体成员需要已有显式检查/视图规则，不合并所有实体模板后声称任意成员存在。
- 数量为零时，写命令沿用无目标失败/无操作语义。读取值必须走现有成功/失败结果合同，不能留下旧临时槽值冒充本次读取结果；若现有接口没有可表达的结果合同，则在实现该读取入口前补充方案审阅。
- 上下文遍历本身不返回隐式汇总值；每个命令的 CommandResult 留在对应回调分支内，不引入默认求和/取最后一项。

## 6. 验收与停止边界

首先交付最短可运行链：给定源码 → 正常标准库解析 → 上下文绑定 → 数据包导出 → 实际命令执行。

必须覆盖的行为：
1. 用户原样示例可编译；每只直接乘客传送到源空间上下文位置，源实体、其他实体和回调后的外层上下文正确。
2. 无目标、无乘客、多个直接乘客及嵌套乘客树；分支次数符合关系语义，不隐式递归所有后代或去重。
3. withPosCtx 的目标与当前执行者不同，明确验证 at 与 as 的独立性；跨维度空间信息不能丢失。
4. 外层位置跨 executor 变化仍有效；更内层改变位置后引用外层位置，以及改变 executor 后引用外层 executor，都不得重绑定到当前分量。
5. 单目标、已知多目标、动态 limit、玩家专用约束；无法证明时出现明确诊断，逐实体回调内 executor 可用于单实体操作。
6. 赋值副本、已支持的参数/返回与普通 lambda 捕获保持访问表达式语义；自由变量重名不会串绑。
7. 回调局部 return、连续兄弟回调、普通同步辅助调用、嵌套时的命令顺序和调用帧恢复。
8. 上下文逃逸、错误来源/跨会话句柄和无效使用诊断；合法内层引用 posCtx 必须通过。
9. 源码编译与 fresh .mclib 导入均能调用新接口；必要标准库重建后用户不依赖测试专用库。

验证方式：
- 先复用已有 LambdaSyntaxTest、NativeSelectorContractTest、MNI 上下文检查和库往返入口；只为新增语义和实际缺陷增加针对性用例。
- 检查实际生成的生产命令，并交给支持所需命令的已有 DSB/执行环境。若已有解释器需要补关系、tp、维度，只补这些验收场景，不建立新的通用模拟器项目。
- 不进行实际游戏运行测试。
- 各实现阶段运行受影响检查；统一类型/库格式改动集成后安排一次整体回归。通过后只因相关修改、失败或具体证据缺口补验。
- 若库编码需要升级，采用现有版本检查并重新生成标准库，验证 fresh 导入；不无条件承诺旧二进制直接读取。
- 新目标沿用技能的验证预算与两次无新证据后重新评估规则；不把预算上限当成目标测试次数。

## 7. 本稿需要审阅的范围选择

建议确认以下默认选择后实施：
1. withPosCtx = at，withEntityCtx = as，onX 沿上下文 executor；不隐式把位置目标同时设为执行者。
2. 普通 entity 复制构造时的目标结构/参数；上下文与其句柄仅允许在活跃的同步作用域中使用。
3. 本期完整覆盖直接目标和关系上下文；用户公开的 IntArray UUID 指针工厂、辅助物品实体生命周期及跨 tick/reload 指针持久化作为后续独立功能。后端为保留活跃句柄而使用 UUID 是内部实现选择，不代表已交付公开持久指针 API。
4. 对“没有实体时读取字段返回什么”沿用可用的现有失败结果合同；若需要新增可空值/Result 接口，先给出具体补充设计，不默认返回零或旧值。

缩写模式、普通 lambda 自动改变 Minecraft 上下文、任意可逃逸上下文对象、完整 execute 命令 DSL、实体集合快照和自动去重不属于本稿实施内容。
